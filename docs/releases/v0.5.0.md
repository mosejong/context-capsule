# Context Capsule v0.5.0

v0.5.0 turns the handoff packet into a lightweight, human-controlled engineering harness. Context Capsule still does not edit code or run arbitrary commands. It now records the task boundary before work and verifies reported changes and evidence after work.

## What Changed

- Added `TASK_CONTRACT.json` to saved Work Handoff packets.
- Added a read-only contract verifier to the Korean web UI, CLI, and FastAPI.
- Blocks forbidden paths, out-of-scope paths, missing HIGH/BLOCKED approval, and failed checks.
- Warns when required verification evidence has not been reported.
- Added ground-truth answers for all 11 external-repository evaluation cases.
- Added a hard-negative metric case: stale README `98.6%` versus authoritative report `98.08%`.
- Added a generated 1k/5k/10k repository audit and explicit `app/web` API contract check.

## Task Contract Example

```powershell
.\context_capsule_cli.bat generate --repo-path . --task "README 수정" --save --json
.\context_capsule_cli.bat verify --contract outputs\...\TASK_CONTRACT.json --changed-file README.md --check scope_review=passed --check test_or_run_result=passed --check acceptance_criteria_review=passed --json
```

## Safety Boundary

- No automatic file edits.
- No automatic shell execution.
- No automatic approval.
- A PASS result still requires final human review.
